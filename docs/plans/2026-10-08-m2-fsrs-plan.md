# M2 implementation plan

Design: [2026-10-08-m2-fsrs-design.md](2026-10-08-m2-fsrs-design.md). Every core task is
test-first (AGENTS.md rule 1): write the failing test, run it red, implement, run it green,
commit. Before each push: `pnpm lint && pnpm typecheck && pnpm test && pnpm build && pnpm test:e2e`.

- Commit `build(core): add ts-fsrs`.

## Task 2 — core `srs/schedule.ts` (test first: `srs/schedule.test.ts`)

Types: `SrsCard` (mirrors the `card` row without ids: `due`, `stability`, `difficulty`,
`elapsedDays`, `scheduledDays`, `learningSteps`, `reps`, `lapses`, `state`, `lastReview`),
`ReviewInput { ts: Date; result; hints; timeMs }`, `ScheduleOptions { easyMs? }`.

Tests:

1. `ratingFor`: correct fast → Easy, correct slow → Good, hint 1/2 → Hard, hint 3 → Again,
   wrong → Again; boundary at exactly `easyMs` is Easy; custom `easyMs`.
2. `reviewCard(null, correct)` → state Learning or Review, reps 1, lastReview = ts, due > ts.
3. A wrong answer on a Review card increments `lapses`, state Relearning, due within minutes.
4. Good reviews spaced by their due dates grow `scheduledDays` monotonically.
5. `replayCard(attempts)` equals folding `reviewCard` one by one; empty → null.
6. Deterministic: same inputs → identical card.

Commits: `test(core): specify FSRS card scheduling`, `feat(core): FSRS cards from attempts`.

## Task 3 — core `srs/counts.ts` (test first)

- `scheduledNodeIds(tree)`: user nodes on `enumerateLines` lines (alternatives excluded,
  black repertoires handled).
- `dueNodeIds(tree, cards: ReadonlyMap<nodeId, SrsCard>, now)`: scheduled nodes with a card
  due ≤ now, in tree (line) order.
- `cardCounts(tree, cards, now, endOfDay)`: `{ total, new, learning, review, dueNow, dueToday,
nextDue }` — cards of non-scheduled nodes ignored; `nextDue` = earliest due > now or null.

Commits: test then feat.

## Task 4 — core review drill (test first, in `drill/drill.test.ts`)

- `DrillState` gains `ask: ReadonlySet<string> | null` (null = line drill, every user move).
- `advance` plays automatically the user moves of the planned line that are not asked; they
  are reported in `SubmitResult.autoMoves` / state `lastOpponentMove` stays for opponents.
- In review mode a completed line yields `phase: 'line-complete'` but no `pass`.
- `startReviewDrill({ tree }, dueIds, options)`: greedy coverage in line order, per-line ask
  sets, each due node asked once; empty → `done`. `repeatLine` re-asks the same set.
- `reviewProgress(state)` → `{ asked, total }` for the counter.

Tests: only due moves are asked; prefix user moves auto-played; a due node shared by two lines
asked once; a line with no due node skipped; wrong answer then replay records `wrong`; no pass
in review; line drill behaviour unchanged (existing tests stay green); black repertoire.

Commits: test then feat.

## Task 5 — core `srs/stats.ts` (test first)

- `dayKey(date)` local `YYYY-MM-DD`; `endOfLocalDay(date)`.
- `fillDays(rows, today, n)` → n consecutive days ending today, zeros where missing, summing
  rows that share a day.
- `streak(days, today)` → consecutive days with attempts > 0, ending today (or yesterday if
  today has none yet).

Commits: test then feat. Export everything from `src/index.ts`.

## Task 6 — db: derived cards and daily stats

Tests in `packages/db/src/storage-m2.test.ts` (memory adapter):

1. `recordAttempt` returns `{ attempt, card }`, card row equals `reviewCard(null, …)`.
2. Second attempt updates the same card (reps 2).
3. `daily_stat` rows for scope `collection` and `kind` with counts per result, new cards, time.
4. `listCards(collectionId)` → `Map<nodeId, SrsCard>`.
5. `dailyStats({ from, to, collectionId? })` returns per-day totals (kind rows summed when no
   collection id).
6. `rebuildDerived()` yields identical cards and stats to the incremental path.
7. `migrate()` backfills cards for attempts recorded without them (simulate by deleting the
   card rows), and is a no-op otherwise.

Implementation: `SqliteStorage.recordAttempt` in `tx`: insert attempt, load card, compute,
upsert card, upsert two `daily_stat` rows (`on conflict do update` with increments).
Update the call sites (drill page) for the new return shape. No schema change needed.

Commits: test then feat.
