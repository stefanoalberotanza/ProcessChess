# ADR 003 — Spaced repetition

- Status: accepted (implemented in M2, see ADR 009)
- Date: 2026-10-08

## Context

The user learns sequences, not isolated positions. Some moves in a line are easy, others are
the ones always forgotten; scheduling the whole line as one item wastes reviews.

## Decision

- Use **FSRS** through **ts-fsrs**.
- **One card per user move in a collection**: a `card` row per `node` with `is_user_move = 1`.
  Opponent moves are replayed automatically and have no card.
- The `card` table mirrors ts-fsrs `Card` (`due`, `stability`, `difficulty`, `elapsed_days`,
  `scheduled_days`, `learning_steps`, `reps`, `lapses`, `state`, `last_review`).
- **Cards are derived from the attempt log (M2)**: a card row is created by the first attempt of
  its node (no row = new move) and updated by every later attempt, in the line drill and in the
  review alike, in the same transaction as the attempt. `reviewCard` / `replayCard` in
  `@processchess/core` are pure and deterministic (ts-fsrs defaults: retention 0.9, short-term
  steps 1m/10m, **fuzz off**), so `Storage.rebuildDerived()` can recompute every card from the
  log; `migrate()` does it when attempts exist without cards (M1 data).
- **Scheduled moves** are the user moves on the lines of the drill (ADR 006): the main user move
  at each decision point. Only they count as new/due and are asked in review. An alternative
  played in a drill gets its own card, which is ignored until it becomes the main move.
- Attempt → rating mapping (confirmed in M2): `correct` → Good, Easy when answered in ≤ 2 s
  (`easyMs`); `hint` → Hard, Again when the hint showed the whole move (level 3);
  `wrong` → Again.
- A review walks lines from the root and asks only the due user moves, playing every other move
  automatically (ADR 009); every move played is appended to `attempt` (ADR 002).
- ts-fsrs is pinned to 5.4.2 (MIT).

## Consequences

- Fine-grained scheduling: weak moves come back sooner without repeating known ones.
- Cards can be recomputed from the `attempt` log if FSRS parameters change.
- When the same position appears in two collections, each collection has its own card;
  sharing knowledge across collections by EPD is a possible later optimisation.
