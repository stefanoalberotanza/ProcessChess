# ADR 008 — Bilingual UI and PWA

- Status: accepted
- Date: 2026-10-08

## Decision

### i18n

- Italian and English, **no i18n library**. `apps/web/src/lib/i18n/en.ts` is the source of the
  keys; `it.ts` is declared `satisfies Messages`, so TypeScript rejects missing or extra keys.
- `t(key, params)` replaces `{name}` placeholders and is reactive on the locale (Svelte rune
  state). The locale comes from `localStorage`, then the browser languages, with a manual
  selector in the header. Every UI string goes through `t()`; dates and percentages use `Intl`.
- Chess notation stays standard (English SAN letters); opening names come from the dataset in
  English.

### PWA

- `static/manifest.webmanifest` with placeholder icons, and SvelteKit's native service worker
  (`src/service-worker.ts`).
- At install the worker precaches the build (app shell, all chunks including the lazy openings
  chunk), static files and prerendered pages, plus the worker bundles and `sqlite3.wasm`, which
  SvelteKit does not list: `scripts/precache-extra.js` writes them to `precache-extra.json` after
  `vite build`. Pages are served from cache by path (ids travel in the query string), so after
  the first visit the app works offline.
- Pages are static (`prerender`, `ssr = false`) with ids in the query string (`/drill?id=…`).

## Consequences

- Updating the app requires a reload once the new service worker activates (it calls
  `skipWaiting`/`clients.claim`); no update prompt yet.
- Playwright tests run against the real static output (`scripts/serve-build.js`), including the
  service worker and OPFS.
